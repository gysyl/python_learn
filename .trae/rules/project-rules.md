# 📦 TraeIDE 项目级规则模板（Python 项目）

本规则适用于当前项目，旨在确保代码质量、环境一致性、可维护性与团队协作效率。

---

## 🟦 1. 项目结构规范
- 所有 Python 代码需放置在 `src/` 或项目主模块目录下。
- 测试文件统一放在 `tests/` 目录，命名格式为 `test_xxx.py`。
- 配置文件（如 `.env`, `config.yaml`, `settings.json`）需集中在 `config/` 目录。
- 避免在项目根目录堆积脚本文件，建议放入 `scripts/`。

---

## 🟩 2. 依赖管理
- 必须使用统一的依赖管理方式（推荐：`requirements.txt` 或 `poetry`）。
- 不允许在项目中混用多个虚拟环境工具。
- 新增依赖时需同步更新依赖文件并说明用途。
- 如使用 `requirements.txt`，需提供：
  - `requirements.txt`（运行依赖）
  - `requirements-dev.txt`（开发依赖）

---

## 🟧 3. 环境一致性（WSL / Docker / Dev Containers）
- 项目必须提供统一的开发环境配置：
  - `Dockerfile`
  - `devcontainer.json`
  - `.dockerignore`
- 所有路径需使用跨平台写法（推荐 `pathlib`）。
- 如涉及 GPU、系统库或 C 扩展，需在容器中明确安装步骤。
- 禁止依赖本地系统环境，所有依赖必须在容器中可复现。

---

## 🟨 4. 编码规范
- 遵循 PEP 8 风格。
- 所有模块需包含必要的文档字符串（docstring）。
- 函数超过 20 行需考虑拆分或抽象。
- 禁止出现魔法数字（magic numbers），需使用常量或配置。
- 对复杂逻辑添加简明中文注释。

---

## 🟥 5. 日志与错误处理
- 使用统一的日志库（如 `logging` 或 `structlog`）。
- 禁止使用裸 `except:`，必须捕获具体异常。
- 所有关键流程需记录日志（启动、结束、错误、关键参数）。
- 错误信息需包含上下文，便于排查。

---

## 🟪 6. 测试规范
- 所有新功能必须包含测试（单元测试或集成测试）。
- 测试覆盖率目标：≥ 80%。
- 测试需可在 Dev Container 中一键运行：
  ```bash
  pytest -q

## 🟫 7. 性能与可扩展性
- 优先优化算法复杂度，而非微优化。
- 对大数据处理需提供流式或批处理方案。
- 如涉及异步任务，需提供同步与异步两种接口说明。
- 对潜在性能瓶颈需在 PR 中说明。

## 🟦 8. 文档与说明
- 项目必须包含 README.md，内容包括：
- 项目简介
- 环境搭建方式（Dev Container）
- 运行方式
- 测试方式
- 目录结构说明
- 如涉及 API，需提供接口文档（OpenAPI / Markdown）

## 🟧 9. 安全规范
- 禁止提交敏感信息（密钥、密码、token）。
- .env 文件必须加入 .gitignore。
- 如涉及用户数据，需遵循最小权限原则。
- 外部接口调用需进行异常处理与超时控制。
